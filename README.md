# Поиск поставщиков продуктов питания

MVP сервиса, который помогает закупщику быстро собрать первичный список поставщиков
продуктов питания: находит компании, собирает сведения из открытых источников,
приводит их к общей структуре и сравнивает по прозрачным критериям.

Проверяемая гипотеза: автоматический поиск, извлечение и нормализация открытых данных
позволяют быстрее сформировать первичный список поставщиков и сокращают объём ручного
просмотра сайтов.

Контрольный живой сценарий: «филе куриное, доставка в Екатеринбург, наличие
документов на продукцию». Демонстрационных компаний в выдаче нет.

## Запуск

Нужен Python 3.10 или новее. Базовый живой поиск работает без внешних ключей.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Приложение откроется на [http://127.0.0.1:7860](http://127.0.0.1:7860). Остановить — `Ctrl+C`.

При необходимости скопируйте `.env.example` в `.env` и заполните дополнительные
ключи. Ключи не попадают в интерфейс и в логи.

## Развёртывание Gradio на Render

Файл `render.yaml` описывает готовый Web Service. Для развёртывания откройте
[Render Blueprint](https://render.com/deploy?repo=https://github.com/muzafarovdan/SupplyRadar),
подключите GitHub и подтвердите создание сервиса `supplyradar`. Во время создания
Render запросит секрет `LLM_API_KEY`.

После сборки приложение будет доступно по постоянному адресу вида:

```text
https://supplyradar.onrender.com
```

Render сам устанавливает `requirements.txt`, запускает `python app.py` и передаёт
приложению внешний порт. Каждый новый коммит в `main` запускает автоматическое
обновление.

При необходимости добавьте в настройках сервиса секреты `TWO_GIS_API_KEY`,
`YANDEX_SEARCH_API_KEY`, `YANDEX_FOLDER_ID` или `BRAVE_SEARCH_API_KEY`. Файл
`.env` публиковать нельзя.

Чтобы закрыть интерфейс логином и паролем, добавьте переменные `APP_USERNAME` и
`APP_PASSWORD`. Если они не заданы, сервис открыт всем по публичной ссылке.
Одновременно выполняется не более одного поиска, чтобы ограничить нагрузку и
расход LLM API. SQLite-кэш и CSV на бесплатном экземпляре могут исчезнуть после
перезапуска; на сам живой поиск это не влияет.

Всегда используются открытый B2B-каталог ProductCenter и публичный API
«Госзатраты» по данным контрактов ЕИС. ProductCenter — это независимый каталог,
в котором производители публикуют товарные карточки и реквизиты. Он не является
государственным реестром, поэтому его сведения маркируются как вторичные.

Ключ 2ГИС необязателен и по умолчанию отключён, чтобы VPN-таймауты не замедляли
выдачу:

```dotenv
TWO_GIS_ENABLED=true
TWO_GIS_API_KEY=ваш_ключ
```

Отдельный ключ для поиска по контрактам не нужен. В поле «Дополнительные запросы
по контрактам» можно указать до двух текстовых синонимов через `|`. Например:

```text
филе грудки куриной | грудка куриная без кости
```

Основная категория всегда ищется автоматически, регион берётся из отдельного поля.
История контракта подтверждает факт прошлой поставки, но не текущее наличие, поэтому
такая компания остаётся кандидатом до проверки сайта или свежего прайс-листа.

Прямое подключение к ЕИС по умолчанию отключено (`EIS_ENABLED=false`), поскольку
backend zakupki.gov.ru периодически отвечает HTTP 503. Данные контрактов при этом
поступают через «Госзатраты», а в карточках сохраняются ссылки на первоисточник ЕИС.

Если прямое подключение понадобится, для ЕИС используется отдельный корневой
сертификат Минцифры, включённый в проект. Не следует отключать проверку TLS. В
`.env` задайте:

```dotenv
EIS_ENABLED=true
EIS_CA_BUNDLE=certs/Russian_Trusted_Root_CA.pem
```

Файл взят с [официальной страницы Госуслуг](https://www.gosuslugi.ru/crt). При его
обновлении нужно повторно сверить издателя, срок действия и SHA-256 отпечаток.

Если заданы `YANDEX_SEARCH_API_KEY` вместе с `YANDEX_FOLDER_ID` или
`BRAVE_SEARCH_API_KEY`, официальный веб-поиск используется первым, а DuckDuckGo
подстраховывает пустую или недоступную выдачу. Найденные HTML-страницы загружаются,
кэшируются и сначала проверяются детерминированными правилами. Если задан
`LLM_API_KEY`, модель дополнительно заполняет пропуски и распознаёт однозначные
синонимы товара:

```dotenv
LLM_API_KEY=ваш_ключ
LLM_MODEL=gpt-4o-mini
LLM_BASE_URL=https://api.openai.com/v1
```

Используется OpenAI-совместимый Chat Completions API со строгим JSON Schema.
Значение из ответа модели принимается только тогда, когда указанный URL был реально
загружен, а дословная цитата присутствует в переданном модели тексте. Без ключа
живой поиск продолжает работать на правилах.

## Какие запросы вводить

В поле «Категория товара» лучше вводить точное название продукта без фраз
«найди», «где купить» и «покажи поставщиков»:

```text
филе куриное
сырники замороженные
масло сливочное 82,5%
рис круглозерный
говядина замороженная
филе минтая
молоко 3,2%
яйцо куриное С1
мука пшеничная высший сорт
картофель очищенный
```

Город или регион указывается отдельно, например `Екатеринбург` или
`Свердловская область`. Объём вводится числом в килограммах. Требования вроде
`собственное производство`, `доставка рефрижератором` или `ветеринарные документы`
можно добавить в поле дополнительных условий.

Для поиска в истории контрактов разрешено до двух дополнительных формулировок
через `|`. Основная категория добавляется автоматически. Примеры:

```text
филе грудки куриной | грудка куриная без кости
сырники творожные замороженные | полуфабрикаты творожные
масло сладкосливочное 82,5% | масло сливочное несолёное
рис круглозерный | крупа рисовая
```

Не стоит смешивать несколько разных товаров в одной категории. Для `масло
сливочное` и `сыр российский` лучше выполнить два отдельных поиска.

Тесты:

```bash
python -m pytest
```

## Что делает сервис

1. Пользователь описывает потребность: категория, регион, объём, требования к доставке
   и документам.
2. Сервис формирует поисковые запросы и получает карточки потенциальных поставщиков.
3. Значения приводятся к общему виду: телефоны к E.164, домены без `www` и меток
   отслеживания, регионы к единым названиям, минимальный заказ к килограммам.
4. Записи одной компании объединяются, источники обеих сохраняются.
5. Формула считает оценку 0–100 и выдаёт расшифровку по каждому баллу.
6. Пользователь видит таблицу, карточку с источниками и цитатами, сравнение
   2–4 компаний, список обработанных ссылок и выгрузку в CSV.

Незаполненные поля показываются явно как «не найдено». Сервис не подставляет
догадки: для закупщика ошибочная цена хуже, чем её отсутствие.

Цена платного доступа каталога не считается ценой товара и не повышает рейтинг.
Если ProductCenter скрывает сведения, интерфейс сообщает, что цена товара не
опубликована, а каталог предлагает платный доступ к закрытой информации. Если на
странице есть настоящая товарная цена, например `300 руб./кг`, показывается именно
она.

```text
app.py                  Gradio-интерфейс и привязка событий
src/config.py           настройки окружения и веса рейтинга

src/search/base.py      контракт источника поставщиков
src/search/clear_spending.py  поставщики из контрактов «Госзатрат»/ЕИС
src/search/two_gis.py   живой поиск карточек организаций через 2ГИС Places API
src/search/eis.py       поиск истории поставок в реестре контрактов ЕИС
src/search/live.py      объединение 2ГИС, веб-поиска и проверки страниц
src/web_search.py       ProductCenter, Yandex, Brave и резервный DuckDuckGo
src/fetching.py         асинхронная загрузка, robots.txt и SQLite-кэш
src/extraction.py       извлечение фактов и подтверждающих цитат из HTML
src/llm_extraction.py   проверяемое заполнение пропусков через LLM
src/normalization.py    приведение значений к общему виду
src/deduplication.py    объединение записей одной компании
src/scoring.py          расчёт оценки и расшифровка
src/storage.py          SQLite: история запусков, карточки, подтверждения
src/export.py           таблицы интерфейса и выгрузка в CSV
src/report.py           карточка, статус запуска, описание методики
src/pipeline.py         последовательность этапов обработки
tests/                  unit-тесты и интеграционные проверки на фикстурах
```

## Модель оценки

Оценку считает формула, а не языковая модель. Языковой модели отводится извлечение
отдельных признаков из текста страницы, а не выставление баллов.

| Критерий | Баллы |
|---|---:|
| Ассортимент подтверждает нужную категорию | +30 |
| Подтверждена работа в нужном регионе | +20 |
| Опубликованы условия доставки | +15 |
| Указан минимальный заказ | +10 |
| Минимальный заказ укладывается в объём запроса | +5 |
| Опубликованы сведения о документах | +10 |
| Найдены прямые контакты | +5 |
| Опубликована цена | +5 |

Штрафы: работа в регионе не подтверждена −10, сведения только из каталога
организаций −5, страницы поставщика не открылись −20. В живом режиме организация
без точного подтверждения товара остаётся кандидатом, а розница, маркетплейсы и
явно нерелевантные компании исключаются.

Веса заданы в `src/config.py` (`ScoringWeights`), поэтому правила оценки меняются
без правки логики расчёта.

## Источники данных

Поиск объединяет товарные карточки и профили производителей ProductCenter,
историю государственных контрактов из «Госзатрат», веб-поиск
Yandex/Brave/DuckDuckGo и, опционально, 2ГИС.
Сбой одного сервиса не обнуляет остальные результаты. Для каждого URL сохраняются
провайдер, исходный запрос и тип источника. Точный товар подтверждается только
буквальным фрагментом загруженной страницы; история контракта показывается как
кандидат, а не как доказательство текущего наличия.

## Выбор технологий

- **Gradio** — интерфейс собирается в одном файле и не требует отдельного фронтенда.
  Для проверки гипотезы важна скорость сборки прототипа, а не гибкость вёрстки.
- **SQLite** — не требует установки сервера, файл базы переносится вместе с проектом.
  Хранит историю запусков и карточки, поэтому результат можно открыть повторно
  и проверить извлечение без обращения к сети.
- **Pydantic** — схема данных описана один раз и используется и для проверки
  входных данных, и для валидации ответа языковой модели.

## Ограничения

- Обрабатываются только публично доступные страницы. Разделы, требующие входа,
  и страницы с защитой от автоматических запросов пропускаются.
- DuckDuckGo используется через неофициальную HTML-выдачу и может временно
  ограничивать запросы; при этом уже найденные результаты сохраняются.
- На текущем этапе разбирается HTML. PDF, таблицы и сайты, требующие JavaScript,
  остаются неподдерживаемыми.
- Сведения о документах означают, что компания упоминает их на сайте.
  Действительность сертификатов в государственных реестрах не проверяется.
- Юридический статус компании и её платёжеспособность не оцениваются.
- Цены и условия на сайтах устаревают: в карточке указана дата проверки.
- Плата за доступ к закрытым данным каталога показывается отдельным пояснением и
  не выдаётся за стоимость продукции.
- Итоговый список — первичная подборка для звонка, а не готовое решение о закупке.
